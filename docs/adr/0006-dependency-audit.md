# 0006 — Dependency audit: the smallest upgrade, one accepted advisory

**Context.** The first real `npm install` (Windows, npm 11, November 2026) reported 13
vulnerabilities (1 moderate, 10 high, 2 critical) and a deprecation warning for ESLint 9.
The version ranges in `package.json` had been written without registry access (ADR 0002),
so nobody had checked them against what was current, and there was no lockfile.

The 13 findings have three root causes. npm counts every package on a vulnerable path,
so one advisory in a small package shows up many times.

| Advisory                                            | Vulnerable package (installed) | Reached through                                                                  | First fixed release                              |
| --------------------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------ |
| GHSA-82fw-gwwq-j7x9, GHSA-qxg6-89mg-rqv8 (moderate) | `@vitest/mocker` 3.2.7         | `vitest` 3.2.7                                                                   | 4.1.12 (and 5.0.3)                               |
| GHSA-5gmw-xhrv-c9v3, GHSA-85c8-ppgw-ccpr (critical) | `tinypool` 1.1.1               | `vitest` 3.2.7, which only accepts tinypool 1.x                                  | tinypool 2.1.2; Vitest 4 no longer uses tinypool |
| GHSA-fc5q-39xc-vjpf (high, ReDoS)                   | `picomatch` 4.0.7              | `fdir`, `tinyglobby` → `vite` 7, `vitest`, `@typescript-eslint/*` 8 (6 packages) | **none** — every version is affected             |

A third Vitest advisory, GHSA-xp26-3454-mjgp, affects only 4.1.11 and 5.0.0-rc.2 to
5.0.2, so it does not apply to 3.2.7 or to 4.1.12 and later.

**Decision.**

- **Vitest `^3.2.0` → `^4.1.12`.** 4.1.12 is the lowest release that clears both
  `@vitest/mocker` advisories, and Vitest 4 drops tinypool, which clears both critical
  findings. That is one major version. `npm audit fix --force` proposed Vitest 5.1.0:
  two majors, and it would not clear the picomatch findings, because Vite and
  typescript-eslint depend on picomatch too. Vitest 4 needs Node 20.19+ and Vite 6+,
  which Vite 7 already requires. None of the configuration Vitest 4 removed
  (`environmentMatchGlobs`, `coverage.all`, the `basic` reporter) is used here, and the
  tests only use `describe`, `it` and `expect`.
- **Vite stays `^7`, typescript-eslint `^8`, ESLint `^9`.** The only finding against
  them is picomatch, and no version of anything fixes that today, so a major upgrade
  would add risk and remove none.
- **The picomatch advisory is accepted and tracked** (superseded: see the update below).
  Exploiting it needs an attacker to
  choose the glob pattern. Here every pattern comes from this repo's own config files
  (`vite.config.ts`, `eslint.config.js`, `tsconfig.json`), and these tools only run on
  developer machines and in CI. None of this code ships: `dist/` is our own code bundled
  by Vite. When picomatch publishes a fixed release, run `npm update picomatch` (or
  `npm audit fix`) and commit the lockfile; if a dependent's range still pins an
  affected version, add an `overrides` entry for picomatch in `package.json`.
- **esbuild's install script is denied** (`npm install-scripts deny esbuild`, recorded
  in `allowScripts` in `package.json`). esbuild's binary arrives as an optional
  dependency for each platform (`@esbuild/win32-x64` on Windows), which the lockfile
  records for every platform. The postinstall script only checks that binary and
  downloads it if it is missing. The check that this is safe: a clean
  `npm ci --ignore-scripts` followed by `npx esbuild --version`, `npm test` and
  `npm run build`. npm 12 will block unreviewed install scripts by default, so the
  decision is recorded now rather than left as a warning.
- **Line endings are LF everywhere** (`.gitattributes`: `* text=auto eol=lf`).
  Prettier's default `endOfLine` is `lf`; a Windows checkout with `core.autocrlf=true`
  had CRLF in every file, so `prettier --check .` failed on all of them.
- **The lockfile is committed.** It is generated by a real install, never by hand.

**Update, 18 November 2026.** GitHub withdrew GHSA-fc5q-39xc-vjpf the same day, on
the grounds that glob patterns are supplied by the caller, the same reasoning as above.
With picomatch still at 4.0.7, `npm audit` now reports 0 vulnerabilities, so nothing
remains accepted. If the advisory is reinstated, the reasoning and the plan above apply
again.

The rest of this decision was verified on Windows from the committed lockfile: a clean
`npm ci --ignore-scripts`, then esbuild 0.28.2 answering `--version`, `npm test`
(Vitest 4.1.12, 187 tests), `npm run build` and `npm run lint` all passed.

**Consequences.**

- `npm audit` should report nothing. Treat any new finding as new.
- ESLint 9 reached end of life on 6 August 2026, so it no longer receives fixes. It is
  not in the audit. Moving to ESLint 10 (with `@eslint/js` 10) is a separate major
  change with its own config review, tracked in `PROGRESS.md`.
- Vitest 4 has now run the suite. `tools/offline/` stays for now; ADR 0002 says why.
